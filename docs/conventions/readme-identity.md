# README identity

How the README of every OzarLand repository looks, so that a visitor recognises the organisation from any entry
point. Adapt it to the repository; do not apply it mechanically. Detail belongs in dedicated pages, not in the README.

## The tagline

**OzarLand: a shared land for better OpenStack operations.**

Use it as written. Its longer form, for the hub and the [mission](../vision.md): *OzarLand is a community-driven space
for OpenStack operators to share knowledge, solve operational challenges, and make OpenStack operations better
together.*

## Layout

| Part | What it holds |
|---|---|
| 🔙 Back-link | `[← OzarLand home](https://github.com/OzarLand/ozarland)` on the first line, in every repository but the hub |
| 🏷️ Header | Centred: emoji and repository name as the title, one bold sentence on what it holds, then badges and a line of anchor links |
| 🧭 Introduction | Two or three sentences: what the repository is for, then `Part of [OzarLand](https://github.com/OzarLand/ozarland): *a shared land for better OpenStack operations.*` |
| 🗂️ Content | Scope, how content is organised, the index, how much each page was checked, as the repository needs |
| 🤝 Contributing | How to ask, share, confirm and add, with links to the issue forms and to `CONTRIBUTING.md` |
| 🌍 Part of OzarLand | The shared closing block below, identical everywhere except the "you are here" marker |
| ⚖️ License | Apache-2.0, and the non-affiliation line |

## Visual language

| Element | Rule |
|---|---|
| Banner | [`assets/ozarland-welcome-banner.jpg`](../../assets/ozarland-welcome-banner.jpg) is used on the organisation profile and the hub README only, at most 720 px wide in a README. Repositories keep the emoji title. A repository with its own banner (`openstack-operator-skills`) keeps it. |
| Repository emoji | 🔧 `openstack-vm-runbooks`, 🏗️ `kolla-ansible-deployment-patterns`, 🧪 `openstack-quick-lab`, 🤖 `openstack-operator-skills`. The hub has none. |
| Status colours | Same Mermaid classes everywhere: grey `#f3f4f6`/`#9ca3af` for draft or neutral, green `#dcfce7`/`#16a34a` for lab-verified or read-only, blue `#dbeafe`/`#2563eb` for validated, amber `#fef3c7`/`#d97706` for experimental or state-changing, red `#fee2e2`/`#dc2626` for destructive. |
| Diagrams | Mermaid, rendered natively by GitHub. No image is added for decoration, and no external service is needed to render one. |
| Badges | shields.io static badges for facts (pages per status, release, license). Status badges are generated by `tools/status_blocks.py`, never edited by hand. |
| Risk markers | ⚠️ state-changing, 🛑 destructive ([risk warnings](risk-warnings.md)). |

## The shared closing block

Copy it before the License section, and mark the current repository with **(you are here)** instead of a link.

```markdown
## 🌍 Part of OzarLand

**OzarLand: a shared land for better OpenStack operations.** It started as a personal initiative by Soufian Zaouam
to share practical OpenStack operational knowledge, and it is meant to grow into a space where operators exchange
experience, document solutions and help each other run more reliable platforms. It is open to everyone: your
knowledge, questions and corrections are welcome.

| | Repository | What it holds |
|:-:|---|---|
| | [ozarland](https://github.com/OzarLand/ozarland) | Start here: newcomer path, community rules, [Discussions](https://github.com/OzarLand/ozarland/discussions) |
| 🔧 | [openstack-vm-runbooks](https://github.com/OzarLand/openstack-vm-runbooks) | Symptom-driven runbooks for instance problems |
| 🏗️ | [kolla-ansible-deployment-patterns](https://github.com/OzarLand/kolla-ansible-deployment-patterns) | Ways to deploy with Kolla-Ansible, compared |
| 🧪 | [openstack-quick-lab](https://github.com/OzarLand/openstack-quick-lab) | A disposable OpenStack lab to practise on |
| 🤖 | [openstack-operator-skills](https://github.com/OzarLand/openstack-operator-skills) | Claude skills that apply this knowledge |
```

When a repository is created or archived, update this block in every repository in the same round of pull requests.
